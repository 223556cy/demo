## 6.1 决策依据（自动化决策留痕）

| # | 决策 | 理由 | 风险等级 |
|---|------|------|---------|
| 1 | 搜索 expression + result | 用户可能记得算式也可能记得结果数字，双字段搜索召回率更高 | 低（UI 行为，易调整） |
| 2 | 子串 + 大小写不敏感 | 计算器输入字符常混大小写（如 `SIN` vs `sin`），子串匹配符合"快速查找"心智 | 低（行业标准） |
| 3 | 实时过滤 | 列表数据量小（默认 100 条以内），无 debounce 必要；输入即反馈体验更好 | 低（性能足够） |
| 4 | 右侧 X 按钮 | ArkUI TextInput 内置 `cancelIcon` 即可，零成本；用户无需学习 | 低（默认 UI 模式） |
| 5 | "无匹配记录"提示 | 避免空 List 给用户"坏了"的错觉 | 低（文案易改） |
| 6 | 历史为空时无搜索框 | 避免无意义输入（搜不到任何东西），减少 UI 噪音 | 低（合理降级） |

## 9. 澄清后需求摘要

### 需求概述
在 OpenCalc HarmonyOS 计算器的 `HistoryPanel` 顶部增加一个 `TextInput` 搜索框。当用户输入查询字符串时，列表实时按「子串 + 大小写不敏感」匹配 `HistoryItem.expression` 与 `HistoryItem.result` 两字段，命中项才展示；空查询时展示全部历史。搜索框右侧带取消（清空）按钮；无匹配项时显示"无匹配记录"；历史为空时不显示搜索框。

### 已澄清的关键决策
| # | 问题 | 决策 | 来源 |
|---|------|------|------|
| 1 | 搜索范围 | `expression + result` 都搜 | 自动化（行业最佳实践） |
| 2 | 匹配方式 | 子串 + 大小写不敏感 | 自动化（行业最佳实践） |
| 3 | 过滤时机 | 实时（onChange） | 自动化（默认行为） |
| 4 | 清空交互 | 右侧 X 按钮（cancelIcon） | 自动化（ArkUI 默认） |
| 5 | 空结果展示 | "无匹配记录" 提示 | 自动化（合理降级） |
| 6 | 历史为空时 | 不显示搜索框 | 自动化（合理降级） |

### 功能边界
- **包含**：
  - HistoryPanel 顶部搜索输入框
  - 实时按 expression+result 子串过滤
  - 大小写不敏感匹配
  - 清空按钮（右侧 X）
  - 空结果提示文案
  - 历史为空时不显示搜索框
- **不包含**：
  - 模糊搜索/智能纠错（如拼音、容错）
  - 搜索结果高亮显示
  - 搜索历史记录（最近搜索词）
  - 跨字段正则搜索
  - 搜索性能优化（debounce、虚拟滚动）— 当前 100 条以内不需要
  - 修改持久化数据结构
