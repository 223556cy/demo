## 1. 系统背景

### 1.1 目的

为 OpenCalc HarmonyOS 计算器用户提供"在历史记录中快速定位历史算式"的能力。当历史记录数量较多（默认上限 100 条）时，用户不再需要肉眼逐条滚动查找，可通过输入关键字子串匹配 `expression` 或 `result` 字段，实时过滤出匹配的历史项。该功能提升历史记录的可发现性与回填使用率（点击历史项会把算式回填到计算器输入区）。

### 1.2 术语与缩写

| 术语/缩写 | 定义 |
| --------- | ---- |
| HistoryItem | 单条历史记录数据结构，含 id / expression / result / timestamp |
| searchQuery | 用户在搜索框中输入的关键字字符串（仅 UI 内存态，不持久化） |
| filteredHistory | 由 searchQuery 过滤后的 HistoryItem 子集 |
| 子串匹配 | expression.toLowerCase().includes(query.toLowerCase()) 形式的非正则匹配 |
| HistoryPanel | CalculatorPage.ets 内的 `@Builder` 历史列表面板 |

#### 3.1.2 关键体验路径（KEP）

- **KEP-01：历史搜索 → 回填算式**
  - 用户目标：找到之前输入过的某条算式并复用
  - 路径（起点→关键步骤→终点）：
    1. 用户点击「▼ 历史」展开历史面板
    2. 在搜索框输入关键字（如 "sin"）
    3. 列表实时过滤显示包含 "sin" 的历史项
    4. 用户点击目标项
    5. 该项 expression 回填到主计算区，历史面板关闭
  - 体验预期（可验证表述）：
    - 输入与列表过滤之间无明显延迟（≤100ms @ 100 条历史）
    - 命中规则可预期："sin" 能匹配 "sin(30)+5!" 这种算式
    - 点击回填行为与原有 onHistoryTap 一致

#### 4.3.1 场景描述

| 场景要素 | 取值 |
| -------- | ---- |

| **G** | 过滤出匹配的历史项 |

| **A** | 用户 |
| **S** | `history.length > 0`，`searchQuery.length > 0` |

#### 4.3.3 用例识别

| 用例编号 | 用例名称 | 用例目的 | 用例描述 | 是否基础用例 |
| -------- | -------- | -------- | -------- | ------------ |
| UC-002-01 | 输入触发实时过滤 | 用户输入即过滤 | 监听 `TextInput.onChange` 重新计算 `filteredHistory` | 是 |

#### 4.3.4 用例 UC-002-01

##### 简要说明
用户输入时实时过滤历史列表。

##### Actor
| 角色 | 类型 |
| ---- | ---- |
| 用户 | 主，人 |

##### 前置条件
`showHistory === true` 且 `history.length > 0`。

##### 最小保证
列表至少显示「无匹配记录」占位，不崩溃。

##### 成功保证
列表中每条 `item` 满足：
- `item.expression.toLowerCase().includes(query.toLowerCase())` 或
- `item.result.toLowerCase().includes(query.toLowerCase())`

##### 触发事件
`TextInput.onChange(query: string)` 回调。

##### 主成功路径
```
1. 用户在搜索框输入字符 C
2. onChange 回调触发
3. 重新计算 filteredHistory = filter(history, C)
4. List 重新渲染 filteredHistory
```

##### 扩展路径
```
1a. 过滤结果为空：
   1. 渲染"无匹配记录"占位文案
2a. 过滤结果非空：
   2. 正常渲染 List，每项维持原有点击/滑动删除行为
```

##### DFX 属性
| DFX 属性 | 是否涉及 | 要求 |
| -------- | -------- | ---- |
| 性能 | 是 | 100 条数据，filter 时延 ≤100ms |
| 兼容性 | 是 | 横/竖屏行为一致 |
| 可测试性 | 是 | 单元测试覆盖过滤函数 |

##### 业务威胁建模需求（消减措施清单）
| 措施编号 | 适用场景 | 风险/威胁面 | 消减措施 | 关联数据/接口 | 验证方式 |
| -------- | -------- | ----------- | -------- | ------------ | -------- |
| TM-002-01 | SC-002 | 极长输入（>1000 字符）导致 filter 慢 | 截断 query 至合理长度（如 200 字符） | TextInput | 手工 + 单元测试 |

##### 可靠性分析需求（FMEA 消减措施清单）
| 异常事件编号 | 异常事件 | 影响 | 消减措施 | 触发检测 | 恢复与兜底 |
| ------------ | -------- | ---- | -------- | -------- | ---------- |
| FM-002-01 | 包含正则元字符（如 `(`, `*`, `?`）的输入被误解析为正则 | 抛错或匹配错乱 | 使用 `String.includes()` 而非 `RegExp`，避免正则注入 | 无 | 用例覆盖 |
| FM-002-02 | 大小写敏感匹配导致用户输入 `SIN` 无法匹配 `sin(30)` | 召回率低 | 统一 `toLowerCase()` | 无 | 单元测试 |

| FM-002-04 | 输入仅空白字符（"   "） | 列表被全部过滤掉 | trim 后再判断；若 trim 后为空则视为无 query | 无 | 单元测试 |

- 单元测试：`filterHistory(history, "(30)")` 命中 expression 含 "(30)" 的项且不抛错
- 手工：100 条历史下输入时无卡顿

否。纯前端内存计算。
