## 7. 语义规则汇总（核心逻辑）

### 7.1 加法场景
- `a+b%` → `(a)+(a)*(b/100)` = `a + a*b/100`
- 例：`50+10%` → `50+50*0.1` = **55** ✅

### 7.2 减法场景
- `a-b%` → `(a)-(a)*(b/100)` = `a - a*b/100`
- 例：`200-15%` → `200-200*0.15` = **170**

### 7.3 乘法场景
- `a*b%` → `a*b/100`（b% 直接展开为 b/100）
- 例：`8×5%` → `8*5/100` = **0.4**

### 7.4 除法场景
- `a/b%` → `a/b/100`（b% 直接展开为 b/100）
- 例：`100÷10%` → `100/10/100` = **0.1**（注意：不是 1000）

### 7.5 负数场景
- `-a+b%` → `(-a)+(-a)*(b/100)`
- 例：`-50+10%` → `-50 + (-50)*0.1` = **-55**

### 7.6 函数场景
- `func(x%)` → 错误（不支持）
- 例：`sin(30%)` → 错误提示

### 7.7 重复 % 场景
- `a%%` → 错误
- `a+b%%` → 错误

### 7.8 错误恢复场景
- 处于 Error 状态时按 `%` → 取消 Error，注入 `%` 到新表达式

### 7.9 连续运算场景
- `50+10%=55` → 用户按 `+` → 用户输入 `5` → 用户按 `%` → 此时 5% 应用到刚输入的 5，表达式变为 `55+5%` → 等于 `55+55*0.05` = **57.75**

> ⚠️ **注**：连续运算的规则是：% 应用到「刚输入的最后一个操作数」（即 5），不是「前一个计算结果」（即 55）。这符合主流计算器行为。

## 9. 待定假设

以下是已默认确认但可在实现阶段微调的项：

| # | 假设 | 理由 |
|---|------|------|
| 1 | `%` 按钮触发立即转换：按下 `%` 后，表达式中前一个数字会被自动改写 | 避免延迟导致用户混淆 |
| 2 | `%` 仅支持二元运算（a op b% 形式），不支持一元 `5%` 单独输入 | 符合主流计算器行为 |
| 3 | 表达式显示时 `%` 字符保持显示，仅在计算时转换 | 用户能看到自己输入的内容 |
| 4 | 错误状态（ErrorFlags）下按 `%` 视为"清错注入新表达式" | 已确认 |
| 5 | 按钮样式：与其他特殊运算符（#、^）保持一致 | 视觉一致性 |
