## 2. 行为规格

### 2.1 表达式预处理协议

`Expression.getCleanExpression(input, '.', ',')` 是唯一入口。percent 在该方法内部通过 `getPercentString` 处理：

```
input  →  replaceSymbols  →  addMultiply  →  getPercentString →  ... →  output
```

### 2.2 macOS 风格百分号规则

| 输入 | 期望计算路径 | 期望结果 |
|------|--------------|----------|
| `50%` | `(50/100)` | 0.5 |
| `50+10%` | `50+50*(10/100)` | 55 |
| `50-10%` | `50-50*(10/100)` | 45 |
| `50×10%` | `50×(10/100)` | 5 |
| `50÷10%` | `50÷(10/100)` | 500 |
| `200-15%` | `200-200*(15/100)` | 170 |
| `(2+3)×10%` | `(2+3)×(10/100)` | 0.5 |
| `50+10%+5%` | `50+50*(10/100)+50*(5/100)`  | 57.5 |
| `50%` 单独 | `50/100` | 0.5 |
| `(-50)+10%` | `-50+(-50)*(10/100)` | -55 |
| `0+10%` | `0+0*(10/100)` | 0 |
| `100+(200×50%)` | `100+200×(50/100)` | 200 |

### 2.3 错误边界

| 输入 | 期望 | 行为 |
|------|------|------|
| `%` （空 base） | 报错"表达式错误" | `ErrorFlags.syntax_error = true` |
| `+10%`（无前导数） | 报错"表达式错误" | `ErrorFlags.syntax_error = true` |
| `50%%` | 50*(0.01/100) ≈ 0.005 | 接受，不报错 |
| `50++10%` | 修正为 50+10% | 容忍连续运算符（沿用既去重规则） |

### 2.4 UI 行为

- 竖屏 / 横屏键盘均显示 `%` 按钮
- 位置：第 1 行（紧邻 AC），第 2 列
- 点击：`onOp('%')` → `expression += '%'`
- 样式：运算符蓝色（与 `+ - × ÷` 一致）
- 反馈：与所有其他按钮一致（无单独振动逻辑）
