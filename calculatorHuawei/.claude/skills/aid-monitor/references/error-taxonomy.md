# 错误分类体系（Error Taxonomy）

## 概述

本文档定义 aid-monitor 使用的错误分类体系。该体系可扩展 — 随着新模式的出现可添加新分类。

## 主分类

| 代码 | 分类名称 | 英文名 | 描述 |
|------|----------|--------|------|
| `CG` | 代码生成 | Code Generation | Agent 生成了错误的代码 |
| `AD` | 架构设计 | Architecture/Design | 设计决策导致实现问题 |
| `WP` | 工作流程 | Workflow Process | 违反 AID 工作流约束 |
| `ET` | 环境工具链 | Environment/Toolchain | 构建配置、依赖、工具链相关失败 |
| `DK` | 领域知识缺口 | Domain Knowledge Gap | 缺少或错误的平台/领域知识 |
| `TS` | 测试相关 | Testing | 测试策略、覆盖率、稳定性问题 |
| `UD` | 用户自定义 | User-Defined | 项目特定的自定义分类 |

---

## 分类详细说明

### CG - 代码生成

Agent 产出的代码本身存在问题。

**子类型：**
- `CG-API`：API 误用（调用了不存在的方法、参数错误、返回值处理错误）
- `CG-DEP`：使用了已废弃的 API 或模式
- `CG-TYPE`：类型错误（类型不匹配、缺少类型声明、泛型使用错误）
- `CG-PLAT`：平台特定错误（HarmonyOS 生命周期、ArkTS 语法限制、组件约束）
- `CG-LOGIC`：逻辑错误（算法错误、边界条件遗漏、状态管理错误）
- `CG-STYLE`：代码风格违规（不符合项目规范、命名不一致）

### AD - 架构设计

设计阶段的决策在实现时暴露问题。

**子类型：**
- `AD-OVER`：过度设计（不必要的抽象、过早优化）
- `AD-MISS`：缺失约束（未考虑并发、未考虑资源限制）
- `AD-PAT`：模式误用（错误的设计模式选择、反模式）
- `AD-DEP`：依赖设计错误（循环依赖、耦合过紧）

### WP - 工作流程

Agent 违反了 AID 工作流的约束或步骤。

**子类型：**
- `WP-SKIP`：跳过步骤（未执行必要的分析或设计步骤）
- `WP-CLASS`：意图分类错误（将需求归入错误类别）
- `WP-SPEC`：规格不完整（产出物缺少关键章节）
- `WP-GATE`：门禁违规（未经用户确认就进入下一阶段）
- `WP-DRIFT`：实现偏离（代码实现与设计规格不一致）

### ET - 环境工具链

与开发环境和工具链相关的失败。

**子类型：**
- `ET-BUILD`：构建配置错误（hvigor 配置、模块依赖）
- `ET-DEP`：依赖问题（版本冲突、缺失依赖）
- `ET-TOOL`：工具使用错误（DevEco CLI 命令错误、HiLog 配置）
- `ET-ENV`：环境假设错误（路径、权限、SDK 版本）

### DK - 领域知识缺口

Agent 缺少特定领域的知识导致错误。

**子类型：**
- `DK-PLAT`：平台机制不了解（HarmonyOS 能力系统、Stage 模型）
- `DK-API`：API 行为假设错误（异步行为、回调时序）
- `DK-LIMIT`：平台限制不了解（内存限制、线程模型、权限模型）
- `DK-CONV`：领域惯例不了解（命名规范、文件组织、最佳实践）

### TS - 测试相关

测试策略或执行中的问题。

**子类型：**
- `TS-COV`：覆盖不足（关键路径未测试）
- `TS-STRAT`：策略错误（测试粒度不当、mock 过度）
- `TS-FLAKY`：测试不稳定（依赖外部状态、时序敏感）
- `TS-ASSERT`：断言错误（验证了错误的行为）

### UD - 用户自定义

项目特定的分类，由用户在使用过程中定义。

**使用方式：**
- 当检测到的错误不属于以上任何分类时，标记为 `UD`
- 用户可以为 `UD` 类型指定自定义子类型名称
- 当某个 `UD` 子类型积累足够多的实例时，考虑将其提升为正式分类

## 严重度定义

| 级别 | 定义 | 示例 |
|------|------|------|
| `high` | 导致功能完全不可用或数据丢失 | 编译失败、运行时崩溃、数据损坏 |
| `medium` | 功能部分受损或需要显著返工 | 逻辑错误、性能问题、设计缺陷需重构 |
| `low` | 不影响功能但违反规范或最佳实践 | 代码风格、命名不一致、冗余代码 |

## 检测信号

以下信号用于自动检测错误：

### 强信号（高置信度）
- 编译/构建失败
- 测试失败
- Lint 错误
- Git revert 提交
- apply-report 中的"问题与解决"章节

### 中信号（需结合上下文判断）
- 同一文件被修改 >3 次
- Fix-on-fix 提交模式（连续修复提交）
- TDD RED 阶段重复次数过多
- 任务被标记为重做

### 弱信号（仅作参考）
- 代码注释中的 TODO/FIXME/HACK
- 异常长的实现时间
- 频繁的 todo 状态切换

## 扩展指南

### 添加新主分类

当满足以下条件时，可以添加新的主分类：
1. 有 ≥5 个实例不属于现有分类
2. 这些实例有明确的共同特征
3. 新分类与现有分类无显著重叠

**步骤：**
1. 选择 2 字母代码（不与现有代码冲突）
2. 在本文档中添加分类说明和子类型
3. 更新知识库 index.md 中的分类列表

### 添加新子类型

直接在对应主分类下添加，格式为 `{主分类}-{子类型缩写}`。
