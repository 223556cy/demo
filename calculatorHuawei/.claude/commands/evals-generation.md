# Evals Generation

## 功能概述

为指定 Skill 生成或扩展 `evals.json` 基准测试文件，支撑 Skill 能力评估。

## 输入

- **目标 Skill**：Skill 名称或目录路径
- **评价标准（可选）**：附加的评价规则文件，如维度定义、评分标准等

## 执行流程

### 第一步：定位目标 Skill

根据用户输入，在项目 `skills/` 目录下查找对应 Skill：

1. 直接匹配：`skills/<category>/<skill-name>/SKILL.md`
2. 模糊匹配：遍历 `skills/` 目录，找到名称匹配的 Skill
3. 路径指定：若用户提供完整路径，直接读取

### 第二步：理解 Skill

读取并分析目标 Skill 的完整定义：

1. **SKILL.md**：职责范围、输入输出格式、约束条件
2. **references/**（如有）：补充规则、模板、参考文档
3. **评价标准文件**（如有）：自定义评价维度、评分规则

### 第三步：分析 Skill 能力边界

基于理解的内容，分析：

| 维度 | 内容 |
|------|------|
| 核心能力 | Skill 主要解决什么问题 |
| 输入类型 | 支持哪些输入格式和场景 |
| 输出格式 | 期望的输出结构是什么 |
| 边界条件 | 输入限制、特殊处理场景 |
| 变体问题 | 同类需求的不同表述方式 |

### 第四步：生成测试用例

生成的用例应覆盖：

- **典型场景**：Skill 核心能力的常规输入
- **边界条件**：输入边界、极端值、特殊格式
- **复杂场景**：多要素组合、嵌套逻辑
- **异常场景**：不合法输入、缺失信息等

### 第五步：检查存量内容

若 Skill 目录下已存在 `evals.json`：

1. 读取现有用例，分析覆盖场景
2. 复用有效用例，补充缺失场景
3. 统一用例格式和风格

### 第六步：输出 evals.json

生成标准格式文件：

```json
{
  "skill_name": "<skill-name>",
  "description": "<评测说明>",
  "evals": [
    {
      "id": 1,
      "prompt": "<测试输入>",
      "expected_output": "<期望输出描述>",
      "files": [],
      "tags": ["<category>"]
    }
  ]
}
```

## 输出

- **evals.json**：生成的评测文件（保存到 `benchmarking/<skill-name>/` 目录）
- **生成报告**：新增用例数、复用用例数、覆盖场景统计
