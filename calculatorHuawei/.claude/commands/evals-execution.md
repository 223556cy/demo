# Evals Execution Command

## 功能概述

对指定 Skill 的能力进行基准测试，基于 `evals.json` 中的测试用例**并行执行**评价，输出详细的评估报告。

## 执行流程

### 第一步：确定目标 Skill

接收用户输入的目标 Skill：
- Skill 名称或路径
- 读取目标 Skill 的 `SKILL.md` 和 `evals.json`

### 第二步：加载评测配置

1. 读取 `evals.json`，解析所有测试用例
2. 确定评测维度（如有自定义评价标准）
3. 读取目标 Skill 的 `SKILL.md`，理解其输入/输出格式和执行方式

### 第三步：并行执行基准测试（关键改进）

**必须使用 subagent 并行执行每个测试用例**，步骤如下：

1. **分发任务**：为 evals.json 中的每个测试用例启动一个独立的 subagent
2. **独立执行**：每个 subagent 按照目标 Skill 的完整输出格式执行
3. **收集结果**：收集所有 subagent 的执行结果

#### subagent 执行指令模板

```
你正在执行 Skill 基准测试。

【目标 Skill】
<skill_name>

【Skill 定义文件路径】
<path_to_skill_md>

【测试用例 #<id>】
- 输入（prompt）：<prompt>

【你的任务】
1. 读取目标 Skill 的 SKILL.md 文件
2. 严格遵循 Skill 定义的输入/输出格式
3. 对上述测试用例的输入执行 Skill，生成完整的输出结果
4. 将你的输出与 expected_output 进行对比分析
5. 给出评分（0-100%）和简要的匹配分析

【输出格式】
请按以下格式输出结果：
---
CASE_ID: <id>
PROMPT: <prompt>
ACTUAL: <实际执行 Skill 后的完整输出>
EXPECTED: <expected_output>
MATCH_ANALYSIS: <对比分析>
SCORE: <评分百分比>
---
```

### 第四步：聚合结果

收集所有 subagent 的执行结果后：
1. 统计通过率（得分 >= 70% 视为通过）
2. 计算平均得分
3. 汇总失败用例详情
4. 生成综合评价报告

### 第五步：评分标准

| 等级 | 说明 | 评分 |
|------|------|------|
| 完全匹配 | 输出完全符合期望 | 100% |
| 部分匹配 | 核心要素满足，存在细节偏差 | 70-99% |
| 基本覆盖 | 覆盖主要需求，缺少次要要素 | 40-69% |
| 不合格 | 未满足基本要求 | 0-39% |

评分要素：
- **意图分类**：是否正确识别需求类型
- **领域映射**：是否覆盖相关技术领域
- **模糊点检测**：是否识别出关键模糊点及严重程度
- **复杂度评估**：评估等级是否合理

## 评价报告模板

```
================================================================================
                          Skill Benchmark 评价报告
================================================================================

【Skill 信息】
Skill 名称   : <skill-name>
评测时间     : <timestamp>
评测用例数   : <total>
执行方式     : 并行（<num> 个 subagent 同时执行）

【总体结果】
通过率       : <passed>/<total> (<percentage>%)
平均得分     : <avg_score>

【详细结果】
| ID  | 状态   | 得分 | 标签 |
|-----|--------|------|------|
| 1   | PASS   | 100% | xxx |
| 2   | FAIL   | 60%  | xxx |
...

【用例详情】
（每个用例的输入、期望输出、实际输出、评分）

### Case #<id>: <tags>
输入        : <prompt>
实际输出    : <actual>
期望输出    : <expected>
匹配分析    : <match_analysis>
评分        : <score>%

【薄弱环节分析】
<分析哪些场景得分较低，可能的原因>

【改进建议】
1. <针对失败用例的优化建议>
2. <针对 Skill 能力补全的建议>

================================================================================
```

## 并行执行约束

- 每个 subagent 必须独立执行完整的 Skill 输出格式
- 不得跳过任何用例，不得简化输出
- 所有 subagent 执行完成后统一聚合结果
- 若 subagent 执行失败，记录为 0% 并记录错误原因

## 输出

- **评价报告**：详细的评测结果和分析
- **通过/失败统计**：各维度通过率
- **失败用例详情**：分析失败原因和优化方向

## 约束

- 评价必须基于 evals.json 中定义的期望输出
- 不得修改 evals.json 中的测试用例
- 评分需有明确的评判依据
- **必须真正执行 Skill，不能仅做静态分析**
