`opencalc/entry/src/main/ets/common/PlotUtils.ets:69-88` 的 `sampleSeries` 构造函数对**所有函数 (包括 tan) 一视同仁**地做均匀采样:

```typescript
const step: number = (xMax - xMin) / (samples - 1)   // 4π/199 ≈ 0.0631
for (let i: number = 0; i < samples; i++) {
  const x: number = xMin + i * step
  const y: number | null = evaluator(expression, x)

```

`computeYRange` [PlotUtils.ets:127-152] 用采样点的 min/max + 10% padding 决定 Y 轴范围,然后 clamp 到 [-1e10, 1e10]。

**为什么 tan 的不同周期"高度不一致"**:

1. **tan 在 [-2π, 2π] 有 4 个垂直渐近线** (x = ±π/2, ±3π/2),采样点**有的周期里正好落得很靠近渐近线**,y 爆炸到 1e9 量级

3. **Y 轴被单边污染**:如果 4 个周期里只有 1 个周期的某个点被 clamp 到 +1e10,**其他 3 个周期里正常范围的 tan 曲线 (±1 ~ ±5) 全部被压扁成贴着 y=0 的水平线**
4. **4π/199 不整除 π**:次要原因,主要矛盾是 ①②③

### 必做 (B) — `computeYRange` 改用百分位 + 渐进截断

```typescript
// PlotUtils.ets:127 computeYRange
const ys: number[] = []
for (let i: number = 0; i < points.length; i++) {
  const y = points[i].y
  if (y === null) continue
  if (!isFinite(y)) continue
  if (Math.abs(y) > 1e6) continue        // 1) 直接丢超界点
  ys.push(y)
}
ys.sort((a, b) => a - b)
const lo: number = ys[Math.floor(ys.length * 0.02)] ?? 0  // 2) 用 2%/98% 百分位
const hi: number = ys[Math.floor(ys.length * 0.98)] ?? 0
let yMin = lo - (hi - lo) * 0.1
let yMax = hi + (hi - lo) * 0.1
yMin = Math.max(yMin, -Y_RANGE_CLAMP)
yMax = Math.min(yMax,  Y_RANGE_CLAMP)
```

成本: 1 个函数,约 15 行改动。**最大收益**: 修了"任意有奇点的函数 (tan/cot/sec/csc/log(x-1) 等) 的 Y 轴自适应",不只 tan。

```typescript
// PlotUtils.ets:81 sampleSeries 循环里

let y: number | null = evaluator(expression, x)

// 检测渐近线: |x - (π/2 + kπ)| < δ, δ = step * 0.5
const k: number = Math.round((x - Math.PI / 2) / Math.PI)
const asymptote: number = Math.PI / 2 + k * Math.PI
if (Math.abs(x - asymptote) < step * 0.5) {
  y = null   // 落到断线,绘图层不画

points[i] = { x, y }
```

## 🐛 Bug: sin(x) 在 GraphPage 上渲染成直线 (Plot-Graph 时序竞态)

**类型**: bugfix (P1 - 用户首次进入绘图页就看到错误结果)
**关联**: Issue #26 (plot-graph)

### 复现步骤
1. 安装 issue #26 的 HAP 到 DevEco 模拟器
2. 启动 OpenCalc → 切到程序员模式
3. 点击工具栏 📈 进入 GraphPage

5. **期望**: 完整正弦波 (3 个波峰/波谷)
6. **实际**: 一条从左下到右上的**直线**

### 根因 (rev-01 已定位)

`opencalc/entry/src/main/ets/pages/GraphPage.ets` 第 46-62 行 `aboutToAppear()` 有**异步时序竞态**:

```typescript
aboutToAppear(): void {
    this.prefs.init().then((): void => { this.loadPrefs() })   // 微任务
    setTimeout((): void => { this.vm.compute() }, 0)           // 宏任务
}
```

ArkTS 事件循环规则: **微任务先于宏任务** 执行。所以:

1. `prefs.init().then(loadPrefs)` 微任务先跑
2. `loadPrefs()` 调 `getRadiansDefault()` → 用户偏好 `radianMode=false` (默认角度)
3. `vm.setRadianMode(!false)` = `setRadianMode(true)` → **`vm.isDegree = true`**
4. 然后宏任务跑 → `vm.compute()` 闭包捕获 `this.isDegree=true`
5. `engine.evaluateAt(e, x, true)` → 把 x 当成**角度**算 sin
6. `Math.sin(x * π/180)`, 在 x∈[-6.28, 6.28] 范围内几乎全是小角度
7. **小角近似** `sin(x°) ≈ x * π/180 ≈ 0.01745 * x` → 200 个采样点几乎线性
8. 渲染出来是一条直线

### 证据 (hilog 抓取)

```
evalAt_in  x=-6.28    deg=true
fn_sin_out ret=-0.10938734658651553  ← sin(-6.28°) ≈ -0.109
evalAt_in  x=+6.28    deg=true
fn_sin_out ret=+0.10938734658651555  ← sin(+6.28°) ≈ +0.109
```

200 个采样点全部满足 `y ≈ x * π/180` (线性) → 画出来是直线。

### 修复建议

把 `vm.compute()` 移到 `loadPrefs` 的 `.then()` 里:

```typescript
aboutToAppear(): void {
    // ...路由参数解析...
    const ctx: common.UIAbilityContext = getContext(this) as common.UIAbilityContext
    this.prefs = new PreferencesStore(ctx)
    this.prefs.init().then((): void => {
      this.loadPrefs()
      this.vm.compute()  // ← 在这里调,等 loadPrefs 完成
    })
    // 删除原来的 setTimeout(() => vm.compute(), 0)
}
```
