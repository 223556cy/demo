# 需求SPEC v1.2 — Issue #28 记忆槽 (M1-M6 + MR) 增量

> 本文件为 Issue #28 简单需求 - 记忆功能的增量 spec。基于 opencalc 计算器既有架构，新增六槽记忆功能。不涉及章节用"不涉及"显式标注。

---

## 系统背景

### 目的

> 为 opencalc 计算器新增经典 6 槽记忆功能：长按数字键 1-6 将当前显示值存入对应 M1-M6 槽位，点 MR 弹出选择菜单调出已存值。对应 Issue #28 描述的"经典功能，演示按钮交互"价值。

### 术语与缩写

| 术语/缩写 | 定义 |
| ----- | --- |
| M1-M6 | 6 个记忆槽位（Memory Slot），与数字键 1-6 一一对应 |
| MR | Memory Recall，调出记忆值 |
| LongPressGesture | HarmonyOS 长按手势（≥500ms 触发） |
| SlotIndex | 槽位下标，取值 1..6（与数字键 index + 1 对齐） |
| display | 当前结果区显示的数值（顶层 state），长按存的是它 |

### 关键体验路径（KEP）

- **KEP-MEM-01（存）**：
  - 用户目标：把当前结果存入某个 M 槽
  - 路径：完成计算→长按数字键 N (1-6) ≥500ms→toast 确认
  - 体验预期（可验证表述）：500ms 内松手不触发；触发后 ≤100ms 出现"已存入 Mx"提示；槽位指示刷新
- **KEP-MEM-02（调出）**：
  - 用户目标：从记忆槽取一个值参与后续计算
  - 路径：点击 MR→弹出 6 槽列表→点击非空槽位→该值进入当前输入流
  - 体验预期（可验证表述）：弹菜单 ≤300ms 出现；空槽灰显且点击无响应；点击后立即填入 display

#### 用例 UC-001-01：saveToSlot

##### 简要说明

用户长按数字键 N（1≤N≤6），把当前 display 值存入第 N 个 M 槽。

##### Actor

| 角色  | 类型（主/次，人/系统） | 与系统的关系 |
| --- | ------------ | ------ |
| 用户 | 主，人 | 通过长按手势触发 |

##### 前置条件

| 场景要素         | 本用例采用的取值（引用 4.2.2） | 对用例的影响点（触发/步骤/分支/数据/DoD） | 处理方式（保持/扩展/拆分用例/拆分场景） |
| ------------ | ------------------ | ------------------------ | --------------------- |
| **T** 生命周期阶段 | 运行中 | trigger 时机 | 保持 |
| **G** 场景目标   | 存当前 display | 数据源 | 保持 |
| **E** 环境     | 模拟器 | UI 自动化可行 | 保持 |
| **A** 参与者    | 用户 | UI 触发 | 保持 |
| **S** 系统状态   | display 数值任意 | 数据源 | 保持 |

##### 最小保证

长按手势被识别，存槽动作进入执行路径（即使 display 为 0 / 空串，也作为合法值存入槽位）。

##### 成功保证（后置条件）

- 对应 M(N) 槽的 value 更新为 display，updatedAt = 当前时间戳
- lastUsedSlotIndex 更新为 N
- 出现 toast "已存入 Mx"

##### 触发事件

数字键 N (1≤N≤6) 的 LongPressGesture 触发（≥500ms 按压）。

##### 主成功路径（基本事件流）

```
1. 用户在计算器页面得到 display 数值
2. 用户长按数字键 N (1≤N≤6) ≥500ms
3. 系统识别为 longPress
4. 系统调用 MemorySlotsStore.saveToSlot(N, display)
5. 系统触发 toast "已存入 Mx"
6. 系统刷新记忆指示 UI
```

##### 扩展路径

```
1a. display 为空（"" / 0 默认值）:
    → 仍按 0 存入；toast 仍显示"已存入 Mx"
2a. 用户在 <500ms 内松手:
    → 不触发 longPress，视为普通点击（在数字键单击场景下进入输入流）；不存槽
3a. 长按数字键 0 / 7 / 8 / 9:
    → 不绑定 longPress 行为；按普通数字键处理
```

#### 用例 UC-002-01：recallFromSlot

##### 简要说明

用户点击 MR 按钮，弹出菜单选槽位，将槽位值加载到当前输入流。

##### Actor

| 角色  | 类型（主/次，人/系统） | 与系统的关系 |
| --- | ------------ | ------ |
| 用户 | 主，人 | 点击 + 列表选择 |

##### 前置条件

| 场景要素         | 本用例采用的取值 | 对用例的影响点 | 处理方式 |
| ------------ | ------------------ | ------------------------ | --------------------- |
| **T** 生命周期阶段 | 运行中 | trigger | 保持 |
| **G** 场景目标   | 调出已存记忆值 | 数据流 | 保持 |
| **S** 系统状态   | 至少 1 个槽位非空 | 按钮可用性 | MR enabled 派生自 anySlotHasValue |

##### 最小保证

MR 按钮在全部为空时禁用；在任一非空时启用。

##### 成功保证（后置条件）

- 用户选择的槽位值被写入当前输入流
- 输入流后续参与"="计算

##### 触发事件

MR 按钮点击事件。

##### 主成功路径

```
1. 用户点击 MR 按钮
2. 系统检查 anySlotHasValue；若为 false 早退（按钮已禁用）
3. 系统弹出 ActionSheet/BottomSheet，列出 M1-M6
4. 用户点击非空槽位 M(N)
5. 系统调用 recallFromSlot(N)
6. 系统将该值写入当前输入流；关闭菜单
```

##### 扩展路径

```
3a. 用户在菜单打开后取消:
    → 关闭菜单，不修改任何状态
4a. 用户点击空槽位:
    → 槽位禁用，不可点
```

| DFX 属性 | 是否涉及 | 要求 |

| 可测试性 | 是 | 弹菜单 → 选择 → 输入流值更新 三步可单测 |
| 可靠性 | 是 | 空槽不可点；非空槽点击 100% 写入 |
| 性能 | 是 | 菜单弹出 ≤300ms |

#### 用例 UC-003-01：memoryActiveIndicator

##### 简要说明

UI 在结果区上方/侧边显示记忆激活标签。

##### 触发事件

```
1. 槽位状态变化
2. 派生 state memoryActiveLabel 重算
```
