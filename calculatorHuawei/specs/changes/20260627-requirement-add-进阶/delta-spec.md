# 需求SPEC v1.2 — Issue #27 增量规格

---

## 系统背景

### 目的

为 OpenCalc 计算器增加分数/小数结果显示切换能力，满足学生用户群体在数学学习中对分数表达式的强需求，提升工具在教育场景下的适用性。

### 术语与缩写

| 术语/缩写 | 定义 |
| --------- | ---- |
| DisplayMode | 结果展示模式枚举：DECIMAL（小数）/ FRACTION（分数） |
| FractionUtil | 浮点数转最简分数的工具类 |
| lastRawResult | 最近一次计算的原始 number 结果 |

#### 用例 UC-001-01：切换结果展示模式

##### 简要说明

允许用户在计算结果的小数显示和分数显示之间自由切换，切换即时生效并持久化。

##### Actor

| 角色 | 类型（主/次，人/系统） | 与系统的关系 |
| ---- | ---------------------- | ------------ |
| 学生用户 | 主，人 | 使用计算器并查看结果 |
| HarmonyOS preferences | 次，系统 | 持久化用户选择 |

##### 前置条件

| 场景要素 | 本用例采用的取值 | 对用例的影响点 | 处理方式 |
| -------- | ---------------- | -------------- | -------- |
| **T** 生命周期阶段 | 运行时 | 触发切换动作 | 保持 |
| **G** 场景目标 | 查看分数结果 | 决定显示内容 | 保持 |
| **E** 环境 | 竖屏 | 切换按钮可见 | 保持 |
| **A** 参与者 | 学生用户 | 交互主体 | 保持 |
| **S** 系统状态 | 有有效结果 | 允许切换并重新格式化 | 保持 |

##### 最小保证

- 用户操作不会导致应用崩溃
- 无效的切换请求被静默忽略

##### 成功保证（后置条件）

- 结果展示区显示对应模式的格式化文本
- 用户的选择被写入持久化存储

##### 触发事件

用户点击结果展示区右上角的分数/小数切换按钮。

##### 主成功路径（基本事件流）

```
1. 用户完成计算，结果展示区显示当前结果（默认小数模式）。
2. 用户点击切换按钮。
3. 系统切换 displayMode 状态（DECIMAL ↔ FRACTION）。
4. 系统将新模式写入 PreferencesStore。
5. 系统根据 lastRawResult 和当前 displayMode 重新格式化结果。
6. 结果展示区更新为新的显示文本。
```

##### 扩展路径

```
3a. 当前无有效结果（lastRawResult 为 0 且未计算）：
    3a.1 系统仍切换模式，但不更新结果文本。
4a. 分数转换失败（如无理数无法精确表示）：
    4a.1 系统自动回退到小数格式化显示。
```
