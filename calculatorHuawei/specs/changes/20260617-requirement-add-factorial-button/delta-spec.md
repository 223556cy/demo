# Delta-Spec: 阶乘按钮 (!) — Issue #21

> 本文档记录相对于现有 OpenCalc 规范(Android 3.2.1 + 现有 HarmonyOS 移植)的新增/变更需求。

---

## 1. 用户故事

> 作为一名科学计算器用户
> 当我需要做组合数学/概率论相关计算时
> 我希望在科学模式下能直接点 `!` 按钮
> 以便在键入 `5` 后一键追加阶乘运算符,得到 120

**验收标准**:
- 竖屏 + 横屏 + 科学模式下,`!` 按钮均可见
- 点 `!` 走与 `%` 一致的 `onOp('!')` 路径
- 实时预览在键入 `5!` 时显示 `120`
- `=` 键按下后,结果字段显示 `120`,expression 记录 `5!`
- 该表达式保存到历史记录

## 2. 功能需求 (Functional)

| ID | 需求 | 优先级 |
|----|------|--------|
| F-1 | 科学模式下,操作行(`!`)按钮可见 | P0 |
| F-2 | 点 `!` 触发 `onOp('!')`,把 `!` 追加到 `expression` | P0 |
| F-3 | `5!`、`0!`、`1!` 求值正确 | P0 |
| F-4 | `(2+3)!` 求值正确(括号 + 阶乘) | P0 |
| F-5 | 多个阶乘可叠加 (`2!+3!=8`) | P1 |
| F-6 | 与 % 兼容 (`5!+10%`) | P1 |
| F-7 | 实时预览在键入 `5!` 时显示 120 | P1 |
| F-8 | 阶乘结果记录到历史 | P2 |

## 3. 非功能需求 (Non-Functional)

| ID | 需求 |
|----|------|
| NF-1 | 不破坏现有 12 个 percent 单元测试 |
| NF-2 | 不引入新三方依赖 |
| NF-3 | 编译时间增加 < 2s(只改一个 ets 文件 + 新增测试) |
| NF-4 | 测试在无 DevEco Studio 环境(纯 Node.js)也可跑 |

## 4. 边界条件

| 场景 | 期望 |
|------|------|
| `5!` | 120 |
| `0!` | 1 |
| `1!` | 1 |
| `(2+3)!` | 120 |
| `2!+3!` | 8 (=2+6) |
| `5!+10%` | 132 (= 120 + 12) |
| `3!×4!` | 144 (= 6×24) |
| `(!)` | ErrorFlags.syntax_error (空基数) |
| 空 expression 点 `!` | ErrorFlags.syntax_error(已有 formatFactorial 边界保护) |

## 5. 不在本次范围

- 浮点阶乘(2.5!)的 UI 提示
- 大数阶乘(>3000)截断提示气泡
- `!!` 双阶乘按键
- 阶乘专用帮助文档
