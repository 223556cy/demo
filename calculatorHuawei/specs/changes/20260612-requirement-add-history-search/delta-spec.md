# 需求SPEC v1.2 — Delta: 历史搜索框

> 本文件为 OpenCalc HarmonyOS 增量需求规格，仅描述**历史搜索框**新增功能对现有 spec 的影响。未涉及的章节视为不涉及。

---

## 系统背景

### 目的

为 OpenCalc HarmonyOS 的历史记录面板新增实时搜索能力。当历史接近 100 条上限时，用户可通过子串匹配快速定位历史算式，提升查找效率。目标人群：需要频繁查找之前计算结果的重度用户。

### 关键体验路径（KEP）

- **KEP-01 — 搜索历史**：
  - 用户目标：从 100 条历史中找到某条算式
  - 路径：打开 HistoryPanel → 看到顶部搜索框 → 键入 "sin" → 列表立即过滤 → 显示匹配 "sin(...)" 的项
  - 体验预期：键入到结果显示 ≤ 50ms，无卡顿

- **KEP-02 — 清空搜索**：
  - 用户目标：清除错误输入
  - 路径：键入 "abc" → 看到右侧 X → 点击 → 搜索词清空 → 列表恢复
  - 体验预期：一键清空，无需手动逐字删除

#### 用例 UC-002-01：子串过滤

##### 简要说明
HistoryPanel 内置实时过滤逻辑。

##### Actor

| 角色 | 类型 | 与系统的关系 |
| --- | ------------ | ------ |
| 主用户 | 主，人 | App 使用者 |

##### 前置条件

| 场景要素 | 本用例采用的取值 | 对用例的影响点 | 处理方式 |
| ------------ | ------------------ | ------------------------ | --------------------- |
| **T** 生命周期阶段 | T2 | 历史已加载 | 保持 |
| **G** 场景目标 | 过滤 | 必须支持 | 保持 |
| **E** 环境 | 任意 | 横竖屏自适应 | 扩展 |
| **A** 参与者 | 主用户 | 无 | 保持 |
| **S** 系统状态 | HistoryPanel 打开 | history 数据就绪 | 保持 |

##### 最小保证
- 输入 "sin" 必须匹配 "sin(30)+5"
- 大小写不敏感（"SIN" 也能匹配 "sin"）

##### 成功保证（后置条件）
- List 仅显示 expression 含 "sin" 的项
- 其他字段（result/timestamp/id）不变

##### 触发事件
- TextInput.onChange(text) 触发

##### 主成功路径（基本事件流）
```
1. 用户在 SearchInput 键入 "sin"
2. @State searchQuery 更新为 "sin"
3. filteredHistory 重新计算
4. List 渲染 filteredHistory
5. 结果数显示更新（如 "3 条匹配"）
```

##### 扩展路径
```
1a. 搜索词为空
   → filteredHistory = history（全部显示）
1b. 搜索词含特殊字符（如 "+", "×"）
   → 当字面量子串处理
2a. 过滤后为空
   → 显示「未找到含 "sin" 的记录」
```
