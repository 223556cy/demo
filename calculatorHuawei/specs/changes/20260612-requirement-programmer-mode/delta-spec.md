# 需求SPEC v1.2 — Delta: 程序员模式

> 本文件为 OpenCalc HarmonyOS 增量需求规格，仅描述**程序员模式**新增功能对现有 spec 的影响。未涉及的章节视为不涉及。

---

## 系统背景

### 目的

为 OpenCalc 计算器新增"程序员模式"，让硬件工程师 / CS 学生 / 嵌入式开发者可在 DEC/BIN/OCT/HEX 间快速切换显示同一数值，并支持位运算（AND/OR/XOR/NOT、<<、>>）和位宽控制（8/16/32/64，signed/unsigned）。目标人群：需要调试 bit flag、分析协议字段、做内存地址计算的专业用户。

### 术语与缩写

| 术语/缩写 | 定义 |
| ----- | --- |
| 程序员模式 | CalculatorMode.Programmer，整数运算 + 进制显示 + 位运算 |
| 进制 | Base，枚举 2/8/10/16 |
| 位宽 | BitWidth，枚举 8/16/32/64 |
| 符号性 | Signedness，枚举 signed / unsigned |
| KEP | Key Experience Path，关键体验路径 |
| KEI | Key Experience Indicator，关键体验指标 |
| FMEA | Failure Mode and Effects Analysis，故障模式与影响分析 |
| DFX | Design for X（非功能属性的设计考量） |
| IR | Initial Requirement，原始需求 |
| SR | System Requirement，系统需求 |

### 关键体验路径（KEP）

- **KEP-01 — 进制互转**：
  - 用户目标：在 DEC/BIN/OCT/HEX 间快速切换查看同一数值
  - 路径：进入程序员模式 → 输入 `255` → 点 BIN Tab → 显示 `11111111` → 点 HEX Tab → 显示 `FF` → 点 OCT Tab → 显示 `377`
  - 体验预期：切换瞬间完成，4 种进制始终同步，无重渲染延迟可感知

- **KEP-02 — 位运算调试**：
  - 用户目标：组合 bit flag 验证协议字段
  - 路径：8 位无符号 → 输入 `0x0F`（HEX 模式）→ `&` `0x03` → `=` → 显示 `0x03`，且 DEC/BIN/OCT 同步更新
  - 体验预期：所有进制同步刷新，HEX 输入可直接键入 A-F 字符

- **KEP-03 — 有符号位宽切换**：
  - 用户目标：验证补码溢出
  - 路径：8 位 signed → 输入 `127`（DEC）→ 切换 unsigned → 显示 `127`（不变）→ 切换 signed → 切到 16 位 → 输入 `256` → DEC 显示 `256`，BIN 显示 `0000000100000000`
  - 体验预期：位宽切换不影响值的真值，只影响显示位数

#### 用例 UC-001-01：切换到程序员模式

##### 简要说明
通过顶部 Tab 切换 CalculatorMode 至 Programmer，触发键盘重渲染并恢复上次保存的位宽/符号/当前进制。

##### Actor

| 角色 | 类型 | 与系统的关系 |
| --- | ------------ | ------ |
| 主用户 | 主，人 | App 使用者 |

##### 前置条件

| 场景要素 | 本用例采用的取值 | 对用例的影响点 | 处理方式 |
| ------------ | ------------------ | ------------------------ | --------------------- |
| **T** 生命周期阶段 | T2 | 启动阶段模式默认基础 | 默认值不强制 |
| **G** 场景目标 | 进入程序员模式 | 必须可达 | 保持 |
| **E** 环境 | 任意屏幕 | 横屏 4 列、竖屏 5 列布局差异 | 扩展 |
| **A** 参与者 | 主用户 | 无 | 保持 |
| **S** 系统状态 | 已加载 | 偏好需异步读取 | 扩展 |

##### 最小保证
- 模式切换后键盘区至少有数字 0-9 与基本算术
- 偏好读取失败时降级为 32 位 signed / DEC

##### 成功保证（后置条件）
- CalculatorMode == Programmer
- 显示区显示 4 种进制
- 键盘呈现 A-F 按钮和位运算按钮

##### 触发事件
- 用户点击顶部 Tab 的"程序员"按钮

##### 主成功路径（基本事件流）
```
1. 用户在 CalculatorPage 顶部点击"程序员"Tab
2. 页面收到 onChange(mode) 事件，更新 state.programmerMode = true
3. PreferencesStore.savePreferences() 异步保存 programmerMode=true
4. 键盘组件根据 state.calculatorMode 切换到 ProgrammerKeypad
5. 显示区出现 4 行进制结果（DEC/BIN/OCT/HEX）
6. 当前激活进制（高亮）默认为 DEC
```

##### 扩展路径
```
1a. 用户从"科学"模式切来
   → 复用历史 expression 缓存；若含 % 或三角函数则清空并提示"程序员模式不支持"
3a. 偏好保存失败
   → 不阻塞 UI，console 记录，下次启动按当前内存态
4a. 横屏（landscape）
   → ProgrammerKeypad 切换为 4 列布局
6a. 偏好中已有非 DEC 激活进制
   → 恢复上次的当前进制
```
